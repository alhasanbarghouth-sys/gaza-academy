# نظام جمعية بسمة للثقافة والفنون — النظام المعلوماتي الموحّد

> هذا الملف يوثّق رابط الموقع الفعلي بعد ربطه بـ Vercel (Overview → Domains).

نظام ويب سحابي كامل (يعمل على الجوال واللابتوب) لإدارة التواصل بين الإدارة والطاقم الميداني: سجل أنشطة يومي للميسرين، طلبات داخلية بين الموظفين والإدارة، تقارير آلية (5W الشهري لليونيسف، وتقرير أوتشا الأسبوعي)، تقارير مالية، مركز ملفات، بحث شامل، ومساعد ذكاء اصطناعي (Gemini) مطّلع على بيانات النظام.

## المكوّنات التقنية (ولماذا)

| الطبقة | الأداة | السبب |
|---|---|---|
| الواجهة والخادم | **Next.js** (React) | إطار واحد للواجهة + منطق الخادم، ينشر مجانًا على Vercel |
| قاعدة البيانات + المصادقة + تخزين الملفات | **Supabase** (PostgreSQL) | بديل "لا كود" لإدارة سيرفر قاعدة بيانات، يعطيك تسجيل دخول، صلاحيات (RLS)، وتخزين ملفات جاهزة من نفس المكان |
| الاستضافة | **Vercel** | ربط مباشر بـ GitHub، كل push ينشر نسخة جديدة تلقائيًا، شهادة HTTPS مجانية |
| الذكاء الاصطناعي | **Gemini API (Google)** | المساعد الذكي في تبويب "المساعد الذكي" — له مستوى استخدام مجاني |

لا حاجة لإدارة أي سيرفر بنفسك — كل شيء "serverless" ومُدار من مزوّدين سحابيين.

## 1) إعداد قاعدة البيانات (Supabase) — مرة واحدة فقط

1. أنشئ حسابًا على [supabase.com](https://supabase.com) (مجاني للبداية).
2. **New Project** → اختر اسمًا (مثلاً `basma-org`) وكلمة مرور لقاعدة البيانات (احتفظ بها).
3. بعد إنشاء المشروع، اذهب إلى **SQL Editor** → **New query**.
4. افتح الملف [`supabase/migrations/0001_init.sql`](./supabase/migrations/0001_init.sql) من هذا المستودع، انسخ محتواه كاملاً، الصقه في المحرر، واضغط **Run**.
   - هذا ينشئ كل الجداول، الأدوار، والصلاحيات (RLS) دفعة واحدة.
4ب. بنفس الطريقة، شغّل [`0002_camps_and_sessions.sql`](./supabase/migrations/0002_camps_and_sessions.sql) — يضيف قائمة المخيمات والنشاط الجماعي المشترك (بحيث لا يُحتسب نفس المستفيدين أكثر من مرة إذا اشتغل عليهم أكثر من ميسر بنفس الوقت).
4ج. ثم [`0003_seed_camps.sql`](./supabase/migrations/0003_seed_camps.sql) — يعبّي قائمة المخيمات بـ 85 موقعًا حقيقيًا من بيانات بسمة الرسمية (تقرير 5W الفعلي + قائمة مشاريع HI/Enable). بعض الأسماء قد تكون نفس الموقع بصياغة مختلفة (مثل "أنصار 15" بعدة كتابات) — راجعها من **إدارة المخيمات** بعد التشغيل وامسح أي تكرار مؤكد.
4د. ثم [`0004_password_policy.sql`](./supabase/migrations/0004_password_policy.sql) — يضيف خاصية "إلزام تغيير كلمة المرور عند أول تسجيل دخول".
4هـ. ثم [`0005_financial_report_filename.sql`](./supabase/migrations/0005_financial_report_filename.sql).
4و. ثم [`0006_public_portal.sql`](./supabase/migrations/0006_public_portal.sql) — يضيف البوابة العامة (مناشدات، بلاغات إساءة).
5. اذهب إلى **Authentication → Providers** وتأكد أن **Email** مفعّل. (لا داعي لتفعيل تسجيل ذاتي — الحسابات تُنشأ فقط من داخل النظام بواسطة المسؤول، وتسجيل الدخول في هذا النظام برقم الجوال لا بالبريد — انظر القسم أدناه).
6. اذهب إلى **Authentication → URL Configuration** وأضف رابط موقعك (بعد نشره على Vercel في الخطوة 3) في **Site URL** و **Redirect URLs**.
7. اذهب إلى **Project Settings → API** وانسخ ثلاث قيم ستحتاجها لاحقًا:
   - `Project URL`
   - `anon public` key
   - `service_role` key (⚠️ سري جدًا — لا تشاركه ولا تضعه في كود يصل للمتصفح)

### تسجيل الدخول برقم الجوال، لا بالبريد الإلكتروني

اسم المستخدم في هذا النظام هو **رقم الجوال**، وكلمة المرور المؤقتة هي **رقم الهوية**. عمليًا، لكل حساب يُنشأ بريد داخلي غير حقيقي (`<رقم الجوال>@basma.local`) لا يُستخدم إلا خلف الكواليس — المستخدم لا يتعامل إلا برقم جواله. لأن رقم الهوية معروف لغالبية الناس، **كل حساب جديد يُطلب منه تغيير كلمة المرور فورًا عند أول تسجيل دخول** قبل الوصول لأي شيء آخر.

### إنشاء أول حساب (مسؤول النظام)

بعد تشغيل ملفات SQL، لا يوجد أي مستخدم بعد. من لوحة Supabase: **Authentication → Users → Add user**، أدخل البريد `<رقم-جوالك-بدون-رموز>@basma.local` (مثال: `0598885630@basma.local`) وكلمة مرور، فعّل **Auto Confirm User**. ثم في **SQL Editor**:
```sql
update public.profiles set role = 'executive_director', phone = '0598885630'
where email = '0598885630@basma.local';
```
سجّل الدخول من الموقع برقم جوالك — ستكون أنت المسؤول الأول.

### إضافة بقية الطاقم

تُضاف حسابات الطاقم من داخل الموقع (**إدارة المستخدمين**). لا تضع كشف الموظفين (أسماء، أرقام جوال، أرقام هوية) داخل هذا المستودع أبدًا.

## 2) مفتاح المساعد الذكي (Google Gemini)

1. ادخل إلى [aistudio.google.com/apikey](https://aistudio.google.com/apikey) بحساب Google.
2. أنشئ مفتاحًا (Create API key) وانسخه.
3. هذا المفتاح يُستخدم فقط من الخادم (لن يظهر للمستخدمين أبدًا). المستوى المجاني له حد استخدام بالدقيقة/اليوم، وقد تستخدم Google البيانات المرسلة عبره لتحسين خدماتها — راجع شروطهم.

---

## 3) النشر على الإنترنت (Vercel)

1. أنشئ حسابًا على [vercel.com](https://vercel.com) وسجّل الدخول بحساب GitHub.
2. **Add New → Project** → اختر هذا المستودع (`gaza-academy` على فرع `claude/basma-org-info-system-4owr23` أو الفرع الرئيسي بعد الدمج).
3. في خطوة **Environment Variables** أضف القيم التالية (من الخطوتين 1 و2 أعلاه):

   | المفتاح | القيمة |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL من Supabase |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role key |
   | `GEMINI_API_KEY` | مفتاح Gemini |

4. اضغط **Deploy**. خلال دقيقة أو دقيقتين سيكون موقعك متاحًا على رابط مثل `basma-org.vercel.app`.
5. (اختياري) من **Project Settings → Domains** يمكنك ربط دومين خاص بالجمعية.
6. أي تعديل لاحق يُرفع (push) على فرع الإنتاج ينشر تلقائيًا نسخة جديدة — لا حاجة لأي خطوة يدوية.

## 4) التطوير محليًا (للمطورين)

```bash
npm install
cp .env.example .env.local   # ثم عبّي القيم الأربع كما في جدول Vercel أعلاه
npm run dev                  # يفتح على http://localhost:3000
```

أوامر مفيدة أخرى:
```bash
npm run build      # بناء إنتاجي (نفس ما يشغّله Vercel)
npm run typecheck  # فحص أنواع TypeScript فقط
```

## 5) هيكلية الأدوار والصلاحيات

| الدور | يرى | يستطيع |
|---|---|---|
| مسؤول النظام / المدير التنفيذي | كل شيء | كل شيء + إدارة المستخدمين |
| مدير المشاريع / منسق | كل الأنشطة والتقارير | توليد تقارير 5W/أوتشا، الرد على الطلبات |
| المحاسب | التقارير المالية، ملفاته | رفع التقارير المالية |
| الممول | التقارير (5W/أوتشا/مالية) للقراءة فقط | استعراض الأثر والتقارير |
| الميسر | أنشطته الخاصة فقط | تسجيل النشاط اليومي، إرسال طلبات |
| موظف | طلباته الخاصة | إرسال طلبات، استخدام المساعد الذكي والملفات |

الصلاحيات مطبّقة على مستوى **قاعدة البيانات نفسها** (Row Level Security في PostgreSQL)، وليس فقط في الواجهة — فحتى لو حاول أحد الالتفاف على الواجهة، قاعدة البيانات ترفض أي طلب بيانات خارج صلاحيات دوره.

## 6) البوابة العامة (بدون تسجيل دخول)

رابط منفصل: `<رابط موقعك>/public` — شاركه مع أي جهة أو شخص من خارج الجمعية. فيه فقط:

- **نظرة عامة**: أرقام إجمالية فقط (عدد المستفيدين، عدد الأنشطة...) — لا أسماء، لا مواقع مخيمات بالتفصيل، لا أي بيانات حسّاسة.
- **تقديم مناشدة** — تصل إلى **إدارة المشاريع والمنسقين فأعلى** (تبويب "المناشدات").
- **الإبلاغ عن إساءة** — يمكن إرساله دون ذكر الاسم، ويصل **حصرًا** إلى المدير التنفيذي ومسؤول النظام (تبويب "بلاغات الإساءة") — لا يراه أي موظف آخر، حتى لو كان من فريق الإدارة.
- **مساعد ذكي عام** — يعرف فقط الأرقام الإجمالية الظاهرة في الصفحة، ولا يصل إطلاقًا إلى الطلبات الداخلية أو الملفات أو التقارير المالية أو بيانات الموظفين. محمي أيضًا بحد أقصى للطلبات لكل زائر حتى لا يستهلك أحد الحصة المجانية لـ Gemini عمدًا.

الرابط الرئيسي للموقع (`/` أو `/login`) يبقى كما هو — خاص بالطاقم فقط، ولا علاقة له بالبوابة العامة.

---

## 7) خارطة الطريق (الإصدار القادم)

هذا الإصدار الأول (MVP) يغطي: تسجيل الدخول والأدوار، سجل النشاط اليومي (بنظام "الجلسة المشتركة" لمنع ازدواجية عدّ المستفيدين)، قائمة المخيمات بالإحداثيات، الطلبات الداخلية، تقارير 5W/أوتشا الآلية، التقارير المالية، مركز الملفات، البحث الشامل، والمساعد الذكي.

تحسينات مقترحة للمرحلة القادمة:
- إشعارات فورية (Realtime) عند تحديث حالة طلب.
- تصدير PDF مصمّم لتقارير 5W/أوتشا بدل الطباعة من المتصفح.
- لوحة تحليلات بيانية (رسوم بيانية) للمدير التنفيذي.
- تطبيق PWA قابل للتثبيت على الجوال (أيقونة + عمل دون اتصال جزئي).
